# 🛡️ THE SOVEREIGN GIT PROTOCOL (CORE)

Standard version control is chaotic. The Sovereign Git Protocol treats the history of a project as a **Sacred Ledger**.

## 🌀 THE PRINCIPLES OF REPO INTEGRITY

### I. Branch Stratification
- **The Mainline (Protected):** The single source of truth. Always deployable. No direct commits allowed.
- **The Development Branch:** Integration point for features. Sub-agentic testing playground.
- **Feature Branches:** Ephemeral, named by ID (e.g., `feat/SSM-101-simd-fix`).

### II. The Atomic Commit Law
- **Mandate:** One commit = One logical change.
- **Rule:** If you must use "and" in the commit message, the commit is too large. Split it.
- **Goal:** Bi-sectable history for 100% accurate bug tracking.

### III. The Safe PR Protocol
Every Pull Request must undergo a 3-stage validation:
1.  **Static Logic Audit:** Linting, types, and formatting (Strophe 15).
2.  **Invariant Test:** High-fidelity spectral and performance verification (Strophe 16).
3.  **Security Scan:** Cryptographic signature check and secret scanning (Strophe 8).
